# 🧩 Course 02: Algorithms & Problem Solving – Level 1
> **Learning how to think and break down logic before writing a single line of code.**

---

## 📌 Overview
After getting the mental model of how computers process data in Course 01, **Course 02** shifted entirely toward pure algorithmic thinking. 

The biggest lesson here: **Programming is not a programming language—a language is just a tool.** Before jumping into C++ syntax, I spent this course tackling **50 core problems** purely through logical breakdown, flowcharts, and structured trace analysis. 

---

## 🔑 Key Concepts & What I Learned

### 1. Algorithmic Thinking & Logical Analysis
- Understanding what a real algorithm is: a structured, language-agnostic series of execution steps.
- Deconstructing raw problem statements into distinct stages: **Inputs $\rightarrow$ Processing & Decisions $\rightarrow$ Outputs**.
- Eliminating "guess-and-check" habits by designing the entire logic path on paper first.

### 2. Visual Logic Design with Flowcharts
- Designing clear, standardized flowcharts to visually map out program flow, conditional branching, and loop logic.
- Building the discipline to test edge cases visually before touching an IDE.

### 3. The 50-Problem Challenge
- Solved **50 structured logic problems** focusing on math, decision logic, and sequential processes.
- Prepared the complete blueprint for these 50 problems, which I later translated into working C++ code in Course 03.

---

## 💡 Personal Reflection & Impact

> *"Jumping into code before learning how to think makes you a weak developer."*

**My Key Takeaway:**  
This course was a game-changer for my confidence. By deliberately removing code syntax from the picture, I learned how to tackle tricky logic without getting distracted by compiler errors. When I finally moved on to C++, I wasn't struggling with *what* to write—only *how* to translate my already-designed flowcharts into C++ code.
